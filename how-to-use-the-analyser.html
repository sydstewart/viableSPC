How to use the StepChange Analyzer

Six steps, from a spreadsheet to a result you can rely on. Each step links to more detail when you need it. Not sure yet what to measure? Start with Why improvement programmes fail.

1 Prepare your file

Save a CSV file with one row per period: a date column and a value column.

  • One row per day, week or month. If your system exports one row per sale or job, the analyser can total them by period for you.
  • Keep periods with no activity as 0 where you can. If your export leaves them out, the analyser will ask what the missing periods mean.
  • Try it first with the sample data on the analyser page (UK or US dates).

2 Load it and read the data check

Drop the file onto the analyser and choose the date column (X-Axis) and the value column (Y-Axis). A preview shows the first values of each, so a wrong column is easy to spot.

The data check appears straight away. It shows how your numbers and dates will be read, rows that will be left out and why, missing periods and where they are, and anything that needs a decision. Read it before you run anything. What the data check shows.

Date Style and Number Style are best left on Auto-detect. If a file cannot be read one way, for example it mixes day-first and month-first dates, the analyser stops and asks rather than guessing.

3 Run it and answer any questions

Press Recalculate Chart. If your file has missing periods, several rows on the same date, or values below a limit (such as <5), a short panel asks how to treat them. Your answers are saved with the file’s settings and shown with the result; Change data choices lets you revisit them.

Start with the default settings (Conf % 99.7, Loops 1,000, Turn Length 5) and leave Seed blank.

4 Read the result

  • Step Change Analysis shows your values as dots, the average of each stage as a blue line, and the CUSUM as a green line.
  • Stage Summary lists each stage’s dates, average and change in %.
  • The other views (X-mR Chart, Run Chart, CUSUM Chart, Raw Data) show the same data in other ways.
  • The Data read as line under the chart confirms how your file was read and how many rows were used.

A staircase of steps in one direction may be one gradual change rather than several separate ones: a smooth, rounded CUSUM is the clue. One gradual change, or several steps?

5 Check it

  • Look at the dots first, and compare the change dates with what you know: when a change was made, when the way data was recorded changed.
  • Check repeatability shows whether the stage dates hold up in repeated runs. Check for autocorrelation looks for neighbouring values that move together, which can make changes look stronger than they are.
  • Every result has a seed. Entering it with the same file and settings reproduces the result exactly. Reproducing a result.

6 Use it with care

A detected change shows that the data shifted, and roughly when, not why it shifted. “No change found” does not prove that nothing changed, especially with only a few data points. Use the results alongside what you know about the process, and get advice from someone experienced in analysing variation when the decision matters.

Exports (PNG and PDF) record the settings, the seed and the data check, so a result can be explained and reproduced later.

The StepChange Analyzer supports process improvement and the retrospective analysis of historical data. It is not a medical device. Intended use.
